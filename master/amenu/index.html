    AMenu#

    Popup (context) menu.

    Header:#include <AUI/Action/AMenu.h>
    CMake:aui_link(my_target PUBLIC aui::views)

    Detailed Description#

    A menu is described with a model - a vector of AMenuItem structures with a name, an optional shortcut hint, and an onAction handler.

    The most common way to show a menu is to override AView::composeContextMenu; it is called when the user right clicks the view (or long presses it on touchscreens). Return an empty model to show nothing.

    class MyView : public AView {
protected:
    AMenuModel composeContextMenu() override {
        return {
            { .name = "Copy", .shortcut = AInput::CMD_CTRL + AInput::C, .onAction = [this] { copy(); } },
            { .type = AMenu::SEPARATOR },
            { .name = "Disabled", .enabled = false },
        };
    }
};

    To show a menu on your own, call AMenu::show(model). Menus are closed with AMenu::close(); AMenu::isOpen() tells whether there's an open menu.

    Appearance#

    Menus are rendered by the platform, so they look native.

    Platform Implementation Example
    Windows HMENU (TrackPopupMenuEx)
    macOS NSMenu
    Linux (GTK4, GNOME) GtkPopoverMenu
    AMenu::setUseSystemMenus(false) AUI-drawn menu

    Note

    The final look of the menu depends on the OS version and, on Linux, on the desktop environment (and its theme). The screenshots above are examples and may differ from what your users see.

    Note

    shortcut is a text hint only; AUI does not register it as a global hotkey. Handle the keys yourself, see Handling input events.

    setGlobalProvider#

    static void AMenu::setGlobalProvider(std::unique_ptr<IMenuProvider> provider)

    Install a custom provider (overrides both the default and the system setting).

    Useful for testing, embedded renderers, or apps that want a fully custom menu look and feel. Pass nullptr to reset to the default factory behaviour. Call from the UI thread; the cached provider is swapped without synchronization.

    setUseSystemMenus#

    static void AMenu::setUseSystemMenus(bool enabled = true)

    Switches context menu rendering between the platform-native and AUI-drawn providers.

    By default (opt out) AUI uses native NSMenu on macOS, HMENU (TrackPopupMenuEx) on Windows and GtkPopoverMenu on Linux with GTK4/libadwaita — giving native appearance, screen reader integration, and system-level animations. Calling setUseSystemMenus(false) opts out and makes AUI draw its own menus for cross-platform theme consistency. On Linux without GTK4 (i.e., plain X11) there is no native context menu API; this flag is a no-op and the AUI-drawn provider is always used. Call from the UI thread; the cached provider is swapped without synchronization.
