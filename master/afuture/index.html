    AFuture#

    Represents a value that will be available at some point in the future.

    Header:#include <AUI/Thread/AFuture.h>
    CMake:aui_link(my_target PUBLIC aui::core)

    Detailed Description#

    Experimental Feature

    This API is experimental. Experimental APIs are likely to contain bugs, might be changed or removed in the future.

    AFuture is the result of an asynchronous operation: a task on a thread pool, a coroutine, a network request, a dialog. It is the C++ counterpart of a JavaScript Promise, a Kotlin Deferred or a C# Task. See Background tasks and timers for an overview and a comparison with those.

    An AFuture is obtained from one of these:

    • AUI_THREADPOOL runs a lambda on the thread pool: 
      AFuture<int> theFuture = AUI_THREADPOOL {
  AThread::sleep(1000); // long operation
  return 123;
};
    • A coroutine, a function returning AFuture that uses co_await or co_return: 
      AFuture<int> longOperation();
AFuture<int> myFunction() {
  int resultOfLongOperation = co_await longOperation();
  co_return resultOfLongOperation + 1;
}
    • AFuture::create() wraps a callback-based API, like new Promise((resolve, reject) => ...) in JavaScript: 
      AFuture<APath> browseForFile() {
  return AFuture<APath>::create([](AFuture<APath>::Resolver resolver) {
    nativeDialog.show([resolver](APath path) { resolver.supplyValue(std::move(path)); });
  });
}
    • AFuture::fromValue() and AFuture::fromException() make a future that is complete already.

    The producer side (AFuture::Resolver) supplies the result; the consumer side (AFuture) gets it. The result is set once: the first supplyValue or supplyException wins, the later ones are ignored. If every resolver is destroyed before the result is supplied, the future fails with AFutureAbandonedException instead of waiting forever.

    The consumer either blocks with operator*, get() or wait(), awaits with co_await, or subscribes with onValue(), onException() and onFinally(). These callbacks are called exactly once: during resolution, on the thread that supplies the result; or right away if the future is complete at subscription time.

    Exceptions are wrapped into AInvocationTargetException. Each future of a co_await chain adds one level, so the chain of causes leads from the outermost coroutine to the original exception.

    AFuture is a reference counted handle, so it is cheap to copy. When the last AFuture of an operation is destroyed, the operation is cancelled: a pending thread pool task is removed from the queue, a running one gets its thread interrupted, a coroutine stops at its next co_await, and callbacks are not called. This is how a window that closes cancels the requests it has started. For "fire and forget", call AFuture::keepAlive(); to hold several futures, use AAsyncHolder.

    When blocking on a pool thread, operator*, get() and wait() work as stackful coroutines: the thread executes other tasks of the pool until the result is available. Be aware of std::unique_lock and similar RAII-based locks held during such a wait. If the awaited task has not been picked up by the pool yet, the waiting thread executes it itself. See AFuture::wait() for details.

    Resolver#

    class AFuture::Resolver

    The producer side of an AFuture. Obtained from AFuture::create(). Supplies the result with supplyValue or supplyException. Copies refer to the same future. When the last copy is destroyed before a result is supplied, the future fails with AFutureAbandonedException.

    A resolver also tells the producer whether anybody still waits: see isCancelled and onCancel, the counterparts of AbortSignal in JavaScript and CancellationToken in C#.

    all#

    static AFuture<std::tuple<aui::impl::future::Storage<Types>...>> AFuture::all(AFuture<Types> . . . futures)

    Completes when every future has a value; fails as soon as one of them fails.

    Returns
    the values, in the order of the arguments; std::monostate in place of `void`.

    The counterpart of Promise.all in JavaScript, awaitAll in Kotlin and Task.WhenAll in C#.

    The returned future holds the futures given to it. When it completes or fails, it drops them, so the ones still running are cancelled unless somebody else holds them. When it is cancelled, they are dropped as well.

    auto [user, avatar] = co_await AFuture<>::all(loadUser(id), loadAvatar(id));

    any#

    static AFuture<std::variant<aui::impl::future::Storage<Types>...>> AFuture::any(AFuture<Types> . . . futures)

    Completes as soon as one of the futures completes or fails, with its value or exception.

    Returns
    the value of the first future to complete; its index in the variant is its position in the arguments.

    The counterpart of Promise.race in JavaScript, select in Kotlin and Task.WhenAny in C#. The other futures are dropped, so they are cancelled unless somebody else holds them.

    auto result = co_await AFuture<>::any(fromCache(key), fromNetwork(key));

    cancel#

    void AFuture::cancel()

    Cancels the operation.

    When cancel() is called, there are 3 possible cases: 1. AFuture's task is not taken by AThreadPool. The task is simply removed from the AThreadPool queue. 2. AFuture's task is being executed. The task's thread is requested for interrupt. 3. AFuture's task is already completed. cancel() does nothing.

    The onValue/onException callbacks are dropped without a call; the producer is notified through Resolver::onCancel. Destroying the last AFuture of the operation calls cancel().

    create#

    static AFuture AFuture::create(Body&& body)

    Makes a future completed by the code of body.

    Arguments
    body
    called right away with a [`AFuture::Resolver`](afuture.md#AFuture::Resolver); it may pass the resolver anywhere: to another thread, to a callback of an older API.

    The counterpart of new Promise((resolve, reject) => ...) in JavaScript, suspendCancellableCoroutine in Kotlin and TaskCompletionSource in C#.

    If body throws, the future fails with that exception. If the resolver is lost before supplying a result, the future fails with AFutureAbandonedException.

    AFuture<int> answer() {
  return AFuture<int>::create([](AFuture<int>::Resolver resolver) {
    AThread::main()->enqueue([resolver] { resolver.supplyValue(42); });
  });
}

    keepAlive#

    void AFuture::keepAlive()

    Keeps the operation running when every AFuture of it is destroyed, until it completes.

    "Fire and forget": by default, destroying the last AFuture cancels the operation. Use keepAlive for an operation whose result nobody waits for, but which has to finish: sending a log, saving a file. The callbacks subscribed with onValue/onException are still called.

    sendAnalytics(event).onException([](const AException& e) { ALogger::warn("Analytics") << e; }).keepAlive();

    onCancel#

    template<aui::invocable Callback >
const AFuture& AFuture::onCancel(Callback&& callback)

    Calls the callback when the future is cancelled before it has a result.

    Cancellation happens by cancel() or when the last AFuture is destroyed. The callback is called on the thread that cancels, right away if the future is cancelled already, and never if the future completes. It must not hold this future, otherwise the future can't be cancelled by destruction.

    A producer that holds the AFuture::Resolver uses Resolver::onCancel instead.

    onValue#

    template<aui::impl::future::OnValueCallback<T> Callback >
const AFuture& AFuture::onValue(Callback&& callback)

    Calls the callback with the value when it is supplied.

    The callback is called on the thread that supplies the value, or right away if the value is already there. It is not called if the future fails or is cancelled, including by the destruction of its last AFuture. To keep the future alive, put it into an AAsyncHolder of your window or object:

    mAsync << functionReturningFuture().onValue(...); // or onException

    then#

    auto AFuture::then(Callback&& callback)

    Continues with the value of this future and returns a future of the result, like then in JavaScript.

    If the callback returns an AFuture<U>, the result is AFuture<U> that completes with it, not AFuture<AFuture<U>>. This is how asynchronous steps are chained without coroutines:

    AFuture<AImage> loadAvatar(AString userId) {
    return fetchUser(std::move(userId)).then([](const User& user) { return fetchImage(user.avatarUrl); });
}

    If the callback throws, the returned future fails with the exception. If this future fails, the returned one fails as well. The returned future holds this one: dropping the returned future drops this one.

    wait#

    void AFuture::wait(AFutureWait flags = AFutureWait::DEFAULT)

    Sleeps if the result is not currently available.

    The task will be executed inside wait() function if the threadpool have not taken the task to execute yet. This behaviour can be disabled by AFutureWait::JUST_WAIT flag.

    Exceptions captured from AFuture's task are not propagated. This function contains AThread::interruptionPoint(): if wait's caller's thread is interrupted, this function throws an AThread::Interrupted exception.

    withTimeout#

    AFuture AFuture::withTimeout(std::chrono::milliseconds duration)

    A future that completes with this one, or fails with ATimeoutException as the cause if this one does not complete in time.

    Works like any(*this, AThread::asyncSleep(duration)), keeping the type of the value. On timeout, this future is cancelled, so its producer can abort the operation (see Resolver::onCancel). The returned future keeps this one alive; cancelling or destroying the returned future cancels this one too.

    try {
    auto reply = co_await sendRequest().withTimeout(10s);
} catch (const AException& e) {
    // timed out, or sendRequest failed
}
